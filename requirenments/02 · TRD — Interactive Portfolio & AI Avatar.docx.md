# **1\. Архитектурное решение v2.0**

Базовый продукт: статическое портфолио \+ пять независимо публикуемых web-демо \+ небольшой сервер ответов \+ утверждённый корпус \+ управляемый интерфейс тура \+ системное озвучивание \+ зацикленная видеозапись Андрея. Интеллект и приложения не зависят от аватара. Обязательные расходы — $0 в месяц в пределах бесплатных тарифов.

Из базовой архитектуры удалены LiveAvatar/Tavus/Simli, voice cloning, media-session API, WebRTC-сервер, платные симуляторы, подписочная PostgreSQL и обязательный векторный сервис. Не создавать эти компоненты «на будущее». Оставить небольшие внутренние интерфейсы для возможной замены, но не реализовывать неиспользуемые адаптеры.

Версия задаёт проектные контракты, а не уже работающие API. Кодовые фрагменты ниже — внутренний дизайн. Конкретная совместимость сборок, качество модели, расход квоты и браузерные голоса ещё не измерены.

| Компонент | Ответственность | Размещение |
| :---- | :---- | :---- |
| Portfolio \+ Guide UI | Страницы, навигация, плеер, чат, тур, доказательства, loop-avatar. | Static Next.js / Pages |

## **1.1. Стек и инфраструктурные ограничения**

Сохраняются TypeScript, Next.js App Router, дизайн-токены, Tailwind, умеренные Motion-анимации и Playwright. Версии фиксировать lockfile после проверки совместимости. Сайт использует output: export; страницы проектов генерируются через generateStaticParams. Runtime POST API, Server Actions, ISR и стандартный серверный image optimizer в static export не закладывать. AI endpoint работает отдельным Worker. [\[N02\]](https://nextjs.org/docs/app/guides/static-exports)

Cloudflare Pages поддерживает static export Next.js и адрес \*.pages.dev. Заголовки CSP и маршрутизацию статики задавать механизмами хостинга, не runtime-настройками Next.js. Внутренняя SPA-навигация сохраняет GuideProvider в корневом layout. Прямой переход на страницу проекта тоже должен работать. [\[N03\]](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/)

Worker использует Web API runtime и AI binding; не предполагать постоянный Node.js-процесс, локальную файловую систему или долгоживущий voice worker. Корпус и небольшой поисковый индекс собираются заранее; тяжёлый indexing не выполняется на каждом запросе. Лимиты CPU, запросов и размера deployment проверяются на Free до выбора библиотек. [\[N06\]](https://developers.cloudflare.com/workers/platform/pricing/)

# **2\. Модель проектов и знаний**

## **2.1. ProjectManifest: не смешивать платформу и размер**

Обязательные поля: projectId, title, summary, role, contribution, verifiedStack, originalPlatforms, demoModes, viewports, scenarios, limitations, permissionStatus, claimIds, evidenceIds, buildCommit, demoVersion, reviewedAt. У каждого режима — механизм выполнения, источник сборки и статус проверки. Unknown не превращается в публичное утверждение.

Ниже — пример схемы, а не реальный проект Андрея. originalPlatforms сообщает платформы исходного продукта; runtime сообщает, что исполняется здесь; viewports — проверенные размеры интерфейса.

{  
  "projectId": "project-alpha",  
  "permissionStatus": "pending",  
  "originalPlatforms": \["ios", "android"\],  
  "demoModes": \[{  
    "id": "browser", "runtime": "web",  
    "kind": "ported-app", "status": "unverified",  
    "origin": "https://demo.example.test"  
  }\],  
  "viewports": \["phone", "tablet", "desktop"\],  
  "scenarios": \[{"id": "core-flow", "resettable": true}\],  
  "claimIds": \[\], "nativeInstallLinks": \[\]  
}

kind принимает original-web / ported-app / reconstruction; видеозапись — отдельный неинтерактивный материал. Кнопки запуска появляются только для approved \+ verified. Платформенные ссылки берутся из manifest, не сочиняются моделью. Перечень пяти приложений заполняется после аудита; кандидаты из исходной версии не считаются уже проверенными. [\[N17\]](https://www.linkedin.com/in/andreitekhtelev/)

## **2.2. CaseStudy, ChallengeCard и Evidence**

CaseStudy содержит продуктовую задачу, аудиторию, период, личную роль, границы ответственности, ограничения, архитектуру, подтверждённый результат и источники. Для каждого проекта нужен хотя бы один ChallengeCard: ситуация → техническая проблема → альтернативы → выбранное решение → реализация → способ проверки → результат → урок.

Для AI-процесса добавляются aiContribution, humanDecision, validationMethod и outcomeEvidence. Например, можно показать исправленный AI-черновик и тест, обнаруживший ошибку; только когда такая история действительно подтверждена. Нельзя автоматически приписывать всем проектам TDD, RAG, offline или многократное ускорение.

Claim связывает конкретное утверждение с sourceIds, projectId, разрешённой формулировкой, статусом и автором проверки. Метрика требует определения, периода, базы сравнения и способа измерения. Evidence содержит тип (экран, ADR, тест, код, измерение), публичный безопасный адрес/выдержку, ревизию и права. Бот цитирует доступный посетителю материал, не закрытый Google Doc.

Persona отделена от фактов: стиль, терминология, длина ответа и примеры речи не разрешают создавать биографию. Общие технические советы помечаются как рекомендации модели; исторические решения и личные уроки — только из утверждённого корпуса.

# **3\. Интерактивные приложения на различных устройствах**

## **3.1. Бесплатный web-first путь**

Для каждого React Native-проекта проверить Expo/React Native Web, зависимости, navigation, storage, auth, native UI и доступ к файлам. Веб-совместимость не следует из одного слова React Native. Экспорт для совместимого проекта: npx expo export \--platform web. [\[N01\]](https://docs.expo.dev/workflow/web/)

Использовать исходную бизнес-логику и интерфейс везде, где это технически возможно. Платформенные различия вынести в Storage.web / Storage.native, Camera.web / Camera.native и аналогичные адаптеры. Для отсутствующего аппаратного API — разрешённые fixture-сценарии, загрузка файла или явно обозначенная симуляция. Не менять production-поведение ради портфолио без отдельной конфигурации demo.

Каждый demo-build получает синтетический seed, reset, детерминированный основной сценарий и список заменённых интеграций. В v1 предпочтительно локальное состояние/IndexedDB и безопасный demo service adapter, без нового платного backend. Это демонстрация настоящей UI/бизнес-логики с подменёнными сервисами, а не доказательство работы production-сервера. Отдельный живой backend разрешён только при подтверждённом нулевом дополнительном счёте и изоляции данных.

Не отправлять реальные SMS, письма, платежи, медицинские записи или запросы с production-ключами. Если основная ценность продукта состоит в такой интеграции, показать безопасный тестовый сценарий с описанием границы. Для закрытого/непереносимого приложения возможна только отдельно согласованная реконструкция; она не считается оригиналом.

## **3.2. Плеер и матрица совместимости**

Плеер предлагает Phone / Tablet / Desktop, горизонтальную ориентацию там, где она подтверждена, полноэкранный режим и самостоятельное открытие демо. На небольшом экране не сжимать планшет до нечитабельности: использовать responsive layout или явно предложить открыть отдельно. Не устанавливать iPhone User-Agent, чтобы имитировать тест iOS.

Разделять три проверки: desktop viewport в Playwright; web-версия в Safari/Chrome на реальном телефоне/планшете; оригинальное нативное приложение на устройстве. Первая проверка не заменяет вторую и третью. Существующие разрешённые App Store/Google Play ссылки могут быть доступны как «Открыть на устройстве», но не обещают нативный запуск внутри браузера.

Настоящий iOS/Android cloud-stream не входит в обязательный нулевой бюджет. Для него не создавать активную кнопку, тариф или обещание доступности. Переход к такому режиму в будущем требует отдельного согласования расходов и повторной проверки платформы.

Состояния плеера: idle → loading → ready → running → completed; отдельные unavailable / error. До ready бот не предлагает выполнить шаг в ещё не загруженном приложении. Только активное демо загружается; остальные не занимают сеть и память.

## **3.3. Безопасный контракт iframe**

type DemoMessage \= {  
  protocol: "portfolio-demo/2";  
  projectId: string;  
  sessionId: string;  
  requestId: string;  
  kind: "ready" | "screen" | "stepComplete" | "ack" | "error";  
  payload: Record\<string, unknown\>;  
};

На обеих сторонах проверять точный origin, event.source, projectId, sessionId и схему payload; targetOrigin не равен \*. requestId нужен для сопоставления и подавления дублей, а не сам по себе как гарантия идемпотентности. Протокол разрешает только конкретные команды selectScenario / reset / highlight. Произвольные JS, URL, DOM selector или shell-команды не исполняются. [\[N11\]](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)

Для reset и перехода со стиранием введённых данных нужен явный запрос/подтверждение. Команду другого проекта или устаревшего turnId отклонять. CSP frame-ancestors, iframe sandbox и Permissions Policy настраиваются под минимальные потребности. Cross-origin storage, сервис-воркер и cookies проверить отдельно; не ослаблять CSP всего портфолио ради одного приложения. [\[N12\]](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)

Адаптер передаёт только безопасные screenId/stepId и статусы; не raw state, адресную книгу, введённые личные данные или access token. Без такого адаптера гид знает только выбранный проект и сценарий, но не «видит» экран пользователя. Тогда остаются ручные кнопки «Готово / Далее».

# **4\. AI-гид как онлайн-интервью**

## **4.1. Три режима и управление контекстом**

Explore: свободное использование приложений, гид доступен по запросу. Tour: согласованный маршрут с небольшими шагами и предлагаемым действием. Interview: вопросы о роли, решениях и сложностях; можно углубляться и сравнивать кейсы. Переключение не обнуляет текущий разговор внутри вкладки.

GuideState содержит mode, activeProjectId, activeDemoMode, viewport, scenarioId, currentScreenId (только если подтверждён), tourId, stepId, visitedEvidenceIds, responseDepth, language и краткую историю. Добавить suspendedTourStep для возврата после уточнения. Хранить в root provider в памяти вкладки; закрытие удаляет разговор, межсессионную память не включать по умолчанию.

Гид начинает с короткого уместного ответа, затем предлагает одно продолжение: показать решение, открыть сценарий или сравнить подходы. Не читает одно и то же приветствие на каждом проекте и не перегружает ответ всеми технологиями. Повествование от первого лица допускается после AI-обозначения только для утверждённого опыта Андрея.

Если вопрос неоднозначен между проектами, гид кратко уточняет контекст, а не угадывает достижение. Он не выдумывает количественные результаты, мысли владельца, доступность для работы или разрешение на контракт. На вопросы о текущих условиях направляет к подтверждённому контакту.

## **4.2. Минимальный pipeline без агентного усложнения**

Порядок запроса: валидировать ввод → определить релевантный проект/тему → найти утверждённые фрагменты → сформировать ограниченный контекст → вызвать модель один раз → проверить структуру, claimIds и действие → показать ответ → по желанию озвучить. Платная модель, отдельный planner, reranker и LLM-judge на каждом запросе не нужны.

В v1 использовать предварительно собранный лексический индекс, aliases EN/RU, точные названия проектов и фильтры по теме. Стартовый подбор — 4–6 фрагментов по 200–450 токенов, общий prompt ориентировочно до 6 000 токенов, ответ до 700 токенов. Это настройки для пилота, не гарантии достаточности. Если retrieval не проходит тесты, сначала улучшить структуру кейсов и синонимы, затем рассмотреть embeddings в подтверждённой бесплатной квоте.

На один turn — один LLM-вызов; не запускать автоматические многошаговые агенты и бесконечный repair JSON. При невалидном ответе показать найденные материалы с обозначением ограничения. Научное или архитектурное рассуждение модели не считается историческим доказательством личной работы.

Модель выбирается по собственным EN/RU-evals, не по размеру или модному имени. Требуются связное техническое объяснение, корректные ссылки и устойчивость к неизвестным вопросам. В Worker конфигурации хранить modelId, generation settings и promptVersion. Проверить, что выбранная модель доступна именно на Free и не требует paid billing. [\[N05\]](https://developers.cloudflare.com/workers-ai/platform/pricing/)

## **4.3. Доказательства и естественная подача**

Корпус должен отвечать на вопросы «что сделал», «почему так», «что не сработало», «как проверил», «что изменил бы», а не только перечислять стек. Для ответа о сложном решении гид выбирает ChallengeCard и связанные evidenceIds. Цитаты показываются компактно под ответом, не озвучиваются как адреса.

Совпадение sourceId со списком разрешённых источников не доказывает смысловую достоверность. Проверка JSON защищает контракт; отдельные evals и ручная проверка защищают качество фактов. При слабой опоре модель сообщает ограничение. «Нет данных» не заменяется общим рассказом, произнесённым как личный опыт.

Для простоты и согласованности v1 возвращает полностью сформированный и валидированный JSON, затем начинает TTS. Токеновый streaming и раннее произнесение частичных ответов откладываются: ошибочный фрагмент уже нельзя отозвать из речи. Во время ожидания — честный индикатор «готовлю ответ», не фиктивная расшифровка мыслей.

# **5\. Инструменты и подтверждённые действия**

| Действие | Разрешённые аргументы | Условие выполнения |
| :---- | :---- | :---- |
| openProject | projectId из manifest | Явная просьба показать проект или выбранный шаг тура. |
| selectViewport | phone / tablet / desktop | Режим поддержан активным демо; не объявляется native-переключением. |
| startScenario | projectId \+ scenarioId | Демо ready; потеря текущих данных отдельно подтверждена. |
| showEvidence | evidenceId \+ допустимый sectionId | Материал одобрен и соответствует проекту. |
| nextTourStep / resumeTour | tourId \+ stepId | Посетитель управляет продолжением; без принудительного перехода. |
| resetDemo | projectId \+ scenarioId | Явный Reset или подтверждение посетителя. |

В v1 выдавать максимум одно изменяющее UI-действие за ответ. Модель выбирает только из разрешённого списка; сервер валидирует, клиент проверяет текущий контекст и исполняет типизированный handler. Никакого произвольного управления браузером или выполнения сгенерированного кода.

Статусы: proposed → executing → confirmed / failed. Сначала «Открываю…», после ack — «Открыто». При ошибке предложить ручной переход. Ответы и future context не должны считать предположение completed. При ручной смене страницы pending-команды отменяются; уже выполненное действие не откатывается выдуманным текстом.

Engineer Mode v1 показывает выбранные источники, карточку решения, безопасные действия и их статус. Метрики добавляются только если реально измеряются. Не публиковать скрытые рассуждения, system prompt, raw traces, private code или секреты. Полноценный граф архитектуры необязателен: достаточно читаемой схемы с привязкой к кейсу.

# **6\. Простой аватар и системный голос**

## **6.1. Материалы и состояния**

Подготовить три небольших публичных файла: poster.jpg, idle.mp4 (необязательно, можно нейтральный кадр), speaking.mp4. Рекомендация для записи — короткие 5–10-секундные фрагменты в одинаковом кадре и освещении. Это производственный совет, не требование avatar-провайдера. Ролик речи зацикливается; исходная аудиодорожка удалена. Личные оригиналы остаются приватными.

Анимация не анализирует фонемы и не синхронизирует губы с конкретными словами. Это намеренная минимальная реализация, разрешённая владельцем. Маленькая панель снижает заметность повторов, но интерфейс всё равно сообщает, что используется записанная анимация и синтетическая речь.

Состояния AvatarView: idle / preparing / speaking / error. При отсутствии звука или reduced motion — нейтральный кадр. Не включать «говорящий рот», пока ответ только генерируется. Не показывать статус «слушаю микрофон», когда микрофон не используется. Пользователь может скрыть лицо, не потеряв чат.

## **6.2. TTS и управление воспроизведением**

Использовать window.speechSynthesis и SpeechSynthesisUtterance. getVoices и voiceschanged определяют реально доступные голоса; выбрать подходящий язык и дать ручной выбор. Предпочтение конкретного имени голоса — только best effort, не гарантия одинакового звучания на всех устройствах. Это не клонированный голос Андрея. [\[N08\]](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)

Speak включается действием посетителя. Одна очередь принадлежит одному SpeechController. Utterance start запускает speaking loop; end/error/cancel останавливают его; pause/resume обрабатываются согласованно. start/end — синхронизация по факту воспроизведения, не точный lip-sync. Текст разбивать на короткие осмысленные части, удаляя разметку и не озвучивая URL/блоки кода. [\[N09\]](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance)

При новом вопросе, Stop, выключении речи, выходе из тура или уходе вкладки в фон: cancel очереди, invalidate generationId, остановить ролик и отвергнуть поздние события. Видео имеет muted, playsInline, loop; отказ video.play не блокирует TTS и чат. Лимит ожидания события TTS и watchdog возвращают интерфейс в idle, если браузер не прислал ожидаемое завершение.

Свойство localService помогает различить локальный и удалённый голос: не обещать, что любой системный TTS работает полностью offline или не отправляет текст внешнему сервису. Предпочитать локальный голос при наличии; отсутствие подходящего не скрывать. При недоступном TTS остаётся текст. [\[N10\]](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)

Микрофон, распознавание речи и естественный голосовой barge-in в v1 не требуются. «Перебить» здесь означает нажать Stop или отправить новый текстовый вопрос. Синхронные субтитры по словам не обязательны: весь ответ виден рядом, опционально подсвечивается текущая произносимая часть.

# **7\. API, состояние и отмена**

Минимальный публичный backend: POST /v1/guide/turn и GET /v1/health. Политика доступа и конфигурация выдаются статикой; avatar start/stop и media callbacks удалены. URL сервиса хранится в public runtime config; ключ провайдера — только в Worker secrets/binding.

POST принимает turnId, generationId, текст вопроса, language, безопасный UI context, ограниченную историю и challenge token. Клиентские поля недоверенные: нельзя передавать role=system, modelId, сырой prompt, source URLs для загрузки или произвольный tool name. Сервер сам выбирает модель, corpusVersion и разрешённые материалы.

type GuideReply \= {  
  turnId: string;  
  generationId: string;  
  corpusVersion: string;  
  mode: "generated" | "curated" | "unavailable";  
  answerText: string;  
  claimIds: string\[\];  
  evidenceIds: string\[\];  
  action?: { type: AllowedAction; args: SafeArgs };  
  followUp?: string;  
};

Turn хранит AbortController и activeGenerationId. Новый вопрос отменяет fetch, очередь TTS и pending-действия предыдущей generation. Отмена fetch не гарантирует прекращения уже начатого provider-compute; ограничение стоимости обеспечивается бесплатным планом, а время работы — лимитом модели/запроса. Устаревший ответ не отображается и не управляет интерфейсом.

SessionId — случайный контекст вкладки, не доказательство личности и не бюджетная защита. История передаётся ограниченно (например, до 6 последних обменов); её содержание не повышает полномочия и не является источником фактов. Нет глобального mutable conversation state в Worker. В v1 не требуется постоянная БД для разговоров.

Клиентский ack фиксирует реально завершённое действие в GuideState и передаётся следующим запросом как ограниченное недоверенное событие. Поскольку инструменты воздействуют только на публичную локальную демонстрацию, отдельный always-on websocket или callback gateway не нужен.

# **8\. Публикация знаний и защита**

Google Drive остаётся рабочим хранилищем документов, не публичным runtime-инструментом бота. Pipeline: выбрать источник → извлечь черновик → подтвердить владельцем → опубликовать claim/evidence → собрать индекс → выполнить eval → активировать corpusVersion. Raw документы не отправляются в LLM целиком только потому, что подключён Drive.

При отзыве источника удалить фрагменты и связанные утверждения, пересобрать корпус, инвалидировать cache и проверить regression. Public source links не ведут к приватным документам. В v1 не реализуется публичный URL-ingest или загрузка посетителем документов: это исключает отдельный класс SSRF/утечек из обязательного объёма.

Инструкции из retrieved текста, истории и пользовательских сообщений не меняют политику. Инструменты имеют минимальные полномочия, ответ модели валидируется до действия, секреты недоступны corpus. Защита не сводится к фразе «игнорируй prompt injection»; она требует раздельных границ данных и исполняемых команд. [\[N15\]](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

Origin allowlist и CORS защищают браузерный сценарий, но не являются аутентификацией против curl. Перед вызовом модели проверять challenge на сервере, входные размеры, допустимые IDs и лимиты. Turnstile Free — кандидат без подписки; токен подтверждается Siteverify, включая hostname/action и запрет повтора. При недоступной проверке AI не вызывается, статическое демо остаётся. [\[N13\]](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) [\[N14\]](https://developers.cloudflare.com/turnstile/plans/)

Для v1: raw audio/video посетителя не собираются; микрофон не запрашивается; история — в памяти вкладки. По умолчанию не писать полный текст вопросов в диагностику. Хранение минимальных обезличенных технических событий ограничить согласованным сроком (стартовое предложение — 7 дней); удалить лишние default logs. Политику обработки у AI/TTS-провайдера проверить отдельно — собственная настройка логов не доказывает отсутствие provider-retention.

# **9\. Нулевой бюджет и деградация**

| Слой | Базовая конфигурация | Поведение при ограничении |
| :---- | :---- | :---- |
| Сайт, видео-петля, демо | Статические файлы на Pages Free. | Не зависят от лимита AI; health/error видны отдельно. |
| AI-ответы | Workers AI Free; только доступная без оплаты модель. | Ошибку квоты обрабатывать без paid fallback. |
| Речь | Системный TTS без покупаемого API. | Текст и неподвижный аватар при отсутствии голоса. |
| Данные и поиск | Утверждённые файлы и build-time index. | Готовые ответы/тур доступны без генерации. |
| Native/живой аватар | Не подключены в v1. | Не предлагаются как скрыто платная обязательная функция. |

На дату проверки Workers AI Free предоставляет 10 000 Neurons в сутки на аккаунт; при превышении запросы завершаются ошибкой, увеличение требует Paid. Это не 10 000 сообщений: расход зависит от модели и токенов. Есть модели с обязательной оплатой, их исключить. Квота общая с другими AI-задачами аккаунта, включая тесты. [\[N05\]](https://developers.cloudflare.com/workers-ai/platform/pricing/)

Статические запросы Pages бесплатны; Functions/Worker имеют отдельные лимиты. У Pages Free указаны 500 сборок в месяц, 20 000 файлов на сайт и 25 MiB на один asset. Loop-video сжать значительно ниже лимита, не публиковать исходный длинный ролик. CI также имеет собственные квоты выбранного аккаунта, их не считать бесконечными. [\[N04\]](https://developers.cloudflare.com/pages/functions/pricing/) [\[N07\]](https://developers.cloudflare.com/pages/platform/limits/)

Денежная защита: не подключать paid plan, платные ключи, автопополнение или платный «резерв». Если аккаунт уже платный, обещание $0 требует отдельной проверенной конфигурации без chargeable usage; не считать лимит frontend надёжной защитой счёта. До запуска зафиксировать plan/settings и путь отказа.

Для сохранения доступности: один AI-запрос на гостя одновременно, ограничение длины вопроса и output, отсутствие фоновой генерации и строгая server-side challenge-проверка. Клиентский cooldown снижает случайные запросы, но не является hard quota. Глобальный денежный потолок задаётся условиями Free, а не localStorage. При существенных злоупотреблениях добавить серверный rate limit только на подтверждённом бесплатном механизме, не выдумывать распределённый счётчик в памяти.

Переходы: generated → curated при quota/timeout/validation error. Curated использует локально доступные готовые карточки и тур, имеет явную подпись и не заявляет, что только что рассудил над новым вопросом. Не повторять неудачный вызов автоматически бесконечно. Лимит AI не лишает посетителя доступа к приложениям.

# **10\. Качество и измеримые критерии**

Все значения — предлагаемые цели. Сайт: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на p75 отдельно mobile/desktop. Лабораторная проверка не заменяет полевые измерения. Голос, аватар и iframe загружать по требованию. [\[N16\]](https://web.dev/articles/vitals)

Гид: цель p50 ≤ 4 с и p95 ≤ 12 с от отправки вопроса до валидированного текстового ответа на тестовой сети; таймаут 20 с с переходом к материалам. Измерять сетевое ожидание, retrieval и inference отдельно. Это не гарантированная скорость бесплатного сервиса. Stop: цель p95 ≤ 500 мс от нажатия до тишины и остановки speaking-loop.

Приложения: 5/5 имеют принятый интерактивный core-flow; не менее 95/100 контролируемых стартов успешны. Каждая включённая комбинация project × runtime × viewport проверяется; unverified не включается молча. Оригинальный native, web-порт и реконструкция имеют разные статусы.

Доступность: клавиатура, видимый focus, читабельные ответы, ARIA для чата, неозвучиваемые лишние live-region повторы, reduced motion, достаточные touch targets, Stop, mute и скрытие аватара. Нет обязательного autoplay и микрофона. Проверить Chrome/Edge/Firefox/Safari, iOS Safari и Android Chrome; версии и реальные устройства указать в release report.

## **10.1. Evaluation: не только FAQ**

Минимум 120 базовых вопросов: 30 о личной роли/результатах; 30 об архитектуре и сложностях; 15 о AI-процессе; 15 unknown/ambiguity; 15 prompt-injection/приватности; 15 о выборе демо и доказательств. На каждый из пяти проектов — минимум 12 предметных вопросов внутри набора. Переводы не считать независимыми примерами; оба языка покрываются явно.

Дополнительно: 15 multi-turn-интервью (по 3 на проект) с уточнениями и сменой темы; 50 детерминированных tool/UI-сценариев; 20 тестов Stop/TTS/loop/fallback. Отдельный holdout хранить вне настройки промпта. Live-прогоны укладывать в бесплатную квоту; повседневный CI использует записанные fixtures, а не оплачиваемый judge.

Порог: ≥95% проверяемых factual claims поддержаны источниками; 0 критических выдумок о роли/результатах; корректные ограничения минимум в 14/15 unknown-кейсах; 49/50 корректных действий; 0 неразрешённых сбросов/переходов/утечек в тестовом наборе. В 15 multi-turn-сценариях возвращение к прерванному шагу и различение проектов проверяются отдельно.

Андрей вручную проверяет смысл утверждений и то, что цитата действительно подтверждает ответ. Наличие sourceId и тестов, написанных AI, не доказывает корректность. Все ошибки превращаются в regression-кейсы; прохождение конечной выборки не является обещанием отсутствия будущих ошибок.

# **11\. CI/CD, наблюдаемость и решения**

PR: typecheck, lint, unit/contract, secret scan, проверка лицензий/зависимостей, Playwright core-flow и content validation. Изменение кейса/промпта/модели запускает соответствующие evals. Никакого генеративного paid inference в каждом PR по умолчанию. Сборки приложений независимы от сайта.

Release manifest связывает codeCommit, demoVersion, corpusVersion, promptVersion, modelId, testReport и утверждённые runtime/viewports. Откат возвращает последнюю проверенную комбинацию, а не только красивую страницу. Kill switches отдельно управляют AI, speech, animation и каждым демо.

Диагностика: успешность загрузки, turn latency, источник/claim coverage в тестах, результат действия, Stop latency, доля curated fallback и доступная AI-квота. Не выводить посетителю выдуманные live-метрики. Публичный Engineer Mode получает только безопасную проекцию.

ADR-01: независимые demo deployments. ADR-02: web-first с честными platform labels. ADR-03: один grounded LLM-turn, не multi-agent. ADR-04: loop-avatar \+ browser TTS. ADR-05: утверждённый корпус, не весь Drive. ADR-06: $0 Free-only и отказ вместо списания. ADR-07: приложения и тур работают без AI. Пересмотр только после измеренной проблемы или нового решения владельца.

Открыто: точные пять проектов и права; перенос native-модулей; сценарии и evidence; реальные iPad/phone проверки; материалы лица; качество EN/RU модели и голосов; аккаунт Free и лимиты. Технический пилот закрывает путь на одном проекте; целевая приёмка требует все пять.
